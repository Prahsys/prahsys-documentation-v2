## Transaction Types

The Prahsys Payments API supports several transaction types. When processing transactions, you can use one of two approaches
depending on your integration method:

1. **Session-based** (Recommended): When using [Pay Portal](doc:pay-portal) or [Pay Session](doc:pay-session), you'll typically
   specify a `session` parameter that references a payment session where card details were securely collected. Payment information can also be stored or modified when a session is created with [Create Session](/reference/createsession) or updated with [Update Session](/reference/updatesession).

2. **Billing-based**: When using [Pay API](doc:direct-pay), you can specify a `billing` object that contains either
   a [token](doc:tokenization) or [Pay API](doc:direct-pay) details.

For security and simplicity, the examples below primarily use tokens with the `billing` approach. Using sessions or tokens is strongly recommended over direct card information to reduce PCI compliance scope.

### Authorization

An authorization reserves funds on a customer's payment method without actually transferring the money. This is useful for verifying that funds are available before fulfilling a payment. Use the [Authorize](/reference/authorize) endpoint for this transaction type.

> Optionally, billing information can be provided in the body if you wish to use Address Verification Service (AVS) for additional validation of the customer details.

```javascript  Session-based approach (recommended)
// Request to authorize funds using a session
const response = await fetch(`https://api.prahsys.com/payments/n1/merchant/{merchantId}/payment/{paymentId}/authorize`, {
  method: "POST",
  headers: {
    Authorization: `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    payment: {
      amount: 12.99, // Only necessary if the payment details aren't stored in the session or if you want to update the payment
    },
    session: {
      id: "SESSION0002742481646J67219140J7",
    },
  }),
});
```

```javascript Billing with token
// Request to authorize funds using a token
const response = await fetch(`https://api.prahsys.com/payments/n1/merchant/{merchantId}/payment/{paymentId}/authorize`, {
  method: "POST",
  headers: {
    Authorization: `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    payment: {
      amount: 12.99,
      billing: {
        token: "9169573510715182",
      },
    },
  }),
});
```

### Capture

A capture completes a previously authorized payment, actually transferring the funds from the customer to your account. Use the [Capture](/reference/capture) endpoint after a successful authorization.

```javascript filename="Server-side JavaScript"
// Request to capture previously authorized funds
const response = await fetch(`https://api.prahsys.com/payments/n1/merchant/{merchantId}/payment/{paymentId}/capture`, {
  method: "PUT",
  headers: {
    Authorization: `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    amount: 12.99, // Can be equal to or less than the authorized amount
  }),
});
```

### Pay

A pay transaction combines authorization and capture into a single step, immediately transferring funds from the customer
to your account. Use the [Pay](/reference/pay) endpoint for this transaction type.

> Optionally, billing information can be provided in the body if you wish to use Address Verification Service (AVS) for additional validation of the customer details.

```javascript Session-based approach (recommended)
// Request to process a payment in one step using a session
const response = await fetch(`https://api.prahsys.com/payments/n1/merchant/{merchantId}/payment/{paymentId}/pay`, {
  method: "POST",
  headers: {
    Authorization: `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    payment: {
      amount: 12.99, // Only necessary if the payment details aren't stored in the session or if you want to update the payment
    },
    session: {
      id: "SESSION0002742481646J67219140J7",
    },
  }),
});
```

```javascript Billing with token
// Request to process a payment in one step using a token
const response = await fetch(`https://api.prahsys.com/payments/n1/merchant/{merchantId}/payment/{paymentId}/pay`, {
  method: "POST",
  headers: {
    Authorization: `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    payment: {
      amount: 12.99,
      billing: {
        token: "9169573510715182",
      },
    },
  }),
});
```

### Refund

A refund returns funds to a customer after a successful capture or pay transaction. Use the [Refund](/reference/refund) endpoint after a captured or paid transaction.

```javascript Refund
// Request to refund a payment
const response = await fetch(`https://api.prahsys.com/payments/n1/merchant/{merchantId}/payment/{paymentId}/refund`, {
  method: "PUT",
  headers: {
    Authorization: `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    amount: 12.99, // Can be equal to or less than the original captured amount
    // Note: No need to specify billing for refunds as it uses the original payment method
  }),
});
```

### Void

A void cancels a pending authorization before it's captured, preventing any funds from being transferred. Use the [Void](/reference/void) endpoint to cancel an uncaptured authorization.

```javascript Void
// Request to void an authorization
const response = await fetch(`https://api.prahsys.com/payments/n1/merchant/{merchantId}/payment/{paymentId}/void`, {
  method: "PUT",
  headers: {
    Authorization: `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    // Each transaction returns a transaction ID in the response. 
	  // Use this ID to reference previous transactions.
    // Note: No need to specify billing for voids as it uses the original payment method
    targetTransactionId: "AUTHORIZE-20250327-192029", 
  }),
});
```

### Verify

Verify card information before processing a payment. Verification just confirms that the information is valid. It does not reserve any funds or check if enough funds are available. Use the [Verify](/reference/verify) endpoint for this transaction type.

> Optionally, billing information can be provided in the body if you wish to use Address Verification Service (AVS) for additional validation of the customer details.

```javascript Session-based approach (recommended)
// Request to authorize funds using a session
const response = await fetch(`https://api.prahsys.com/payments/n1/merchant/{merchantId}/payment/{paymentId}/verify`, {
  method: "POST",
  headers: {
    Authorization: `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    session: {
      id: "SESSION0002742481646J67219140J7",
    },
  }),
});
```

Using [Pay API](doc:direct-pay):

```javascript Billing with card info
// Request to authorize funds using a token
const response = await fetch(`https://api.prahsys.com/payments/n1/merchant/{merchantId}/payment/{paymentId}/verify`, {
  method: "POST",
  headers: {
    Authorization: `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    payment: {
      billing: {
        card: {
          number: "4111111111111111",
          expiry: {
            month: "12",
            year: "25",
          },
          securityCode: "123",
        },
      },
    }
  }),
});
```

## Retrieving Transaction Details

You can retrieve details of a specific transaction using the transaction ID which is returned in all transaction responses. Use the [Get Transaction](/reference/gettransaction) endpoint:

```javascript Get Transaction
const response = await fetch( `https://api.prahsys.com/payments/n1/merchant/{merchantId}/payment/{paymentId}/transaction/${transactionId}`,
  {
    method: "GET",
    headers: {
      Authorization: `Bearer ${apiKey}`,
    },
  },
);
```

## Common Transaction Scenarios

### Auth-Capture Flow

The auth-capture flow is commonly used for e-commerce:

1. Create a session with [Create Session](/reference/createsession) or a token with [Create Token](/reference/createtoken)
2. Authorize at checkout with [Authorize](/reference/authorize) to verify funds
3. Capture with [Capture](/reference/capture) when order is shipped

#### Using a Session (Recommended)

This example uses the [Authorize](/reference/authorize) and [Capture](/reference/capture) endpoints with a session.

```javascript Session Authorization
// Step 1: Already have a session (SESSION0002742481646J67219140J7)

// Step 2: Authorize
const authResponse = await fetch(
  `https://api.prahsys.com/payments/n1/merchant/{merchantId}/payment/{paymentId}/authorize`,
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${apiKey}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      payment: {
        // Only necessary if the payment details aren't stored in the session or
				// if you want to update the payment
        amount: 12.99, 
      },
      session: {
        id: "SESSION0002742481646J67219140J7",
      },
    }),
  },
);
const transaction = await authResponse.json();

// Step 3: Later, when the order ships, capture the payment
const captureResponse = await fetch(
  `https://api.prahsys.com/payments/n1/merchant/{merchantId}/payment/{paymentId}/capture`,
  {
    method: "PUT",
    headers: {
      Authorization: `Bearer ${apiKey}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      amount: 12.99,
    }),
  },
);
```

#### Using a Token

This example uses the [Authorize](/reference/authorize) and [Capture](/reference/capture) endpoints with a token.

### Pay Flow

The pay flow is used for immediate payment:

1. Create a session with [Create Session](/reference/createsession) or a token with [Create Token](/reference/createtoken)
2. Process payment in a single step with [Pay](/reference/pay)
3. Refund with [Refund](/reference/refund) if necessary

#### Using a Session (Recommended)

This example uses the [Pay](/reference/pay) and [Refund](/reference/refund) endpoints with a session.

```javascript filename="Server-side JavaScript - Session-based approach"
// Step 1: Already have a session (SESSION0002742481646J67219140J7)

// Step 2: Pay
const payResponse = await fetch(`https://api.prahsys.com/payments/n1/merchant/{merchantId}/payment/{paymentId}/pay`, {
  method: "POST",
  headers: {
    Authorization: `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    payment: {
      amount: 12.99, // Only necessary if the payment details aren't stored in the session or if you want to update the payment
    },
    session: {
      id: "SESSION0002742481646J67219140J7",
    },
  }),
});
const transaction = await payResponse.json();

// Step 3: If needed, refund the payment
const refundResponse = await fetch(`https://api.prahsys.com/payments/n1/merchant/{merchantId}/payment/{paymentId}/refund`, {
  method: "PUT",
  headers: {
    Authorization: `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    amount: 12.99,
  }),
});
```
